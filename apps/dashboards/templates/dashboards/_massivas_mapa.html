Como ler o mapa

▲ triângulo vermelho: a caixa por onde começar. ▼ triângulo verde-escuro: a última caixa que continua no ar antes dela — é ela que fecha o trecho. ✕: o provável rompimento, entre as duas. Os três saem de inferência de topologia: o sistema segue o cabo do projeto e vê quem caiu, não a fibra.

⌂ casa: cliente — vermelho está fora agora, verde já voltou. ■ quadrado laranja: caixa (CTO) afetada. ■ quadrado verde-escuro: caixa vizinha da mesma PON que continua no ar — é ela que delimita o trecho. ◆ losango roxo: caixa de emenda perto do evento, onde o cabo é aberto. ★ estrela azul: POP.

{% comment %} O estilo da linha carrega o significado: tracejado é inferência de cadastro, cheio é traçado de verdade. Até 2026-09-19 não havia linha cheia nenhuma aqui, porque não havia geometria — o spike R2 mostrou que ela existe na API (ver `_map_solid_path_trace`). {% endcomment %}

As linhas tracejadas são vínculo de cadastro, não o caminho da fibra: a cinza liga cada caixa ao POP que a alimenta, a laranja liga a caixa mais próxima do POP às demais afetadas. A linha roxa e cheia é diferente: {% comment %} Estas frases ficam numa linha só de propósito: um teste garante que elas chegam inteiras ao HTML, e quebrá-las no meio faz a asserção falhar (a quebra vira espaço em branco no meio da string). {% endcomment %} é o traçado do cabo desenhado no projeto do InMap, e só aparece para os cabos que passam perto das caixas afetadas. Mesmo ela é cadastro, não leitura: diz por onde o projeto passa a fibra, nunca onde ela rompeu. A tela aponta trecho suspeito e cabo candidato, nunca "cabo X rompido".
